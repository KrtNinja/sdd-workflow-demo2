# 005 — Доступ после передачи

Тип: поведение
Основание: FR-6, FR-11 (серверная часть)
Зависимости: 003
Половины: backend (tasks-core) + frontend, принимаются вместе
Результат: прежний исполнитель больше не видит и не меняет переданную задачу

## Контракты
- contracts/tasks-core.openapi.yaml — существующие получение, список и сохранение задачи (не меняется)

## Общая приёмка (собранное приложение)
AC-005-1 Ссылка после передачи
  WHEN Анна передала TASK-42 Борису
   AND открыла ссылку на TASK-42
  THEN показано «Нет доступа к задаче»

AC-005-2 Руководитель видит
  WHEN Анна передала TASK-42 Борису
   AND Вера открыла TASK-42
  THEN исполнитель — Борис

## Backend-половина
AC-005-B1 Список
  WHEN Анна передала TASK-42 Борису
  THEN в «Моих задачах» Анны TASK-42 нет, у Бориса есть

AC-005-B2 Получение
  WHEN Анна запрашивает TASK-42 после передачи
  THEN отказ в доступе

AC-005-B3 Сохранение после передачи
  WHEN Анна сохраняет изменения TASK-42 после передачи
  THEN отказ в доступе, задача не изменилась

## Frontend-половина
AC-005-F1 Нет доступа
  WHEN API вернул отказ в доступе при открытии задачи
  THEN показано «Нет доступа к задаче»

## Границы
Вне slice: реакция открытой карточки на отказ при сохранении (FR-11, клиентская часть) и на
сообщение о передаче — 008. Правило «задачу видят исполнитель и руководитель» уже действует,
slice проверяет, что после передачи оно применяется к новому исполнителю.

## Открытые вопросы к Dev Spec
- Каким отказом сервер отвечает на сохранение после передачи: общим «нет доступа» или NOT_ASSIGNEE? От этого зависит, как 008 отличит «задачу передали» от прочих отказов.

## Definition of Done
- Все AC-005-* закрыты тестами с AC-ID в названиях
- Обе половины влиты, общая приёмка пройдена
- Dev Spec соответствует реализованному, Change удалены
