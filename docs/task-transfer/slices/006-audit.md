# 006 — Аудит передачи

Тип: поведение
Основание: FR-13, NFR-3, NFR-4
Зависимости: 001, 003
Половины: только backend — tasks-core (публикация) + audit (запись), два Change, два PR, принимаются вместе
Результат: каждая передача появляется в журнале аудита и не теряется

## Контракты
- contracts/events/task-transferred.audit.schema.json — не меняется

## Общая приёмка (собранное приложение)
AC-006-1 Запись в журнале
  WHEN Анна передала TASK-42 Борису с причиной «Ухожу в отпуск» 26.10.2026 в 14:05
  THEN в интерфейсе аудита администратор видит запись
       «Анна Петрова → Борис Иванов, TASK-42, 26.10.2026 14:05, «Ухожу в отпуск»»

## Backend-половина
tasks-core:
AC-006-B1 Событие на передачу
  WHEN передача TASK-42 успешна
  THEN публикуется событие по контракту с задачей, кто, кому, когда, причиной

AC-006-B2 Нет события без передачи
  WHEN передача отклонена (любая ошибка 003, 004)
  THEN событие не публикуется

AC-006-B3 Сбой доставки
  WHEN доставка событий недоступна в момент передачи
  THEN передача успешна
   AND после восстановления доставки событие опубликовано

audit:
AC-006-B4 Запись
  WHEN получено событие о передаче TASK-42
  THEN в журнале запись: кто, кому, когда, причина

AC-006-B5 Скорость
  WHEN доставка доступна
  THEN p95 от передачи до появления записи ≤ 1 с

AC-006-B6 Видимость
  WHEN журнал открывает не администратор
  THEN записей о передаче он не видит

## Границы
Вне slice: порядок записей при быстрых передачах (009); realtime (007).
Конфликт с 007: оба добавляют публикацию события в tasks-core в одну и ту же операцию
передачи — договориться, кто первым вводит механизм гарантированной публикации (ADR).

## Открытые вопросы к Dev Spec
- При повторной доставке одного события: в журнале одна запись или дубль допустим? Dev Spec требует только «не теряется».
- AC-006-B6: журнал аудита уже ограничен администраторами, или это нужно сделать для новых записей?

## Definition of Done
- Все AC-006-* закрыты тестами с AC-ID в названиях
- Оба PR (tasks-core, audit) влиты, общая приёмка пройдена
- Решение о гарантированной доставке оформлено в ADR
- Dev Spec соответствует реализованному, Change удалены
