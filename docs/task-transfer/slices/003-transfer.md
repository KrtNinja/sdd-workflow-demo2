# 003 — Передача задачи

Тип: поведение
Основание: FR-1, FR-3, FR-4, FR-8, NFR-1
Зависимости: 001, 002
Половины: backend (tasks-core) + frontend, принимаются вместе
Результат: исполнитель передаёт задачу с причиной, и она сразу переходит к получателю

## Контракты
- contracts/tasks-core.openapi.yaml — передача задачи (не меняется)
- tasks-core: domain/errors/TaskTransferErrors.ts — NOT_ASSIGNEE, INVALID_REASON (не меняется)

## Общая приёмка (собранное приложение)
AC-003-1 Успешная передача
  WHEN Анна в карточке TASK-42 нажала «Передать»
   AND выбрала Бориса Иванова, указала причину «Ухожу в отпуск»
   AND подтвердила
  THEN Анна в «Моих задачах», показано «Задача TASK-42 передана: Борис Иванов»
   AND TASK-42 в списке Анны нет
   AND при входе Бориса TASK-42 в его «Моих задачах» со статусом «В работе»

## Backend-половина
AC-003-B1 Передача
  WHEN Анна передаёт TASK-42 Борису с причиной «Ухожу в отпуск»
  THEN ответ успешный; исполнитель TASK-42 — Борис, статус «В работе»

AC-003-B2 Только исполнитель
  WHEN Вера передаёт TASK-42 Борису
  THEN ошибка NOT_ASSIGNEE, исполнитель не изменился

AC-003-B3 Причина
  WHEN причина пустая, из пробелов или 2049 символов
  THEN ошибка INVALID_REASON, исполнитель не изменился
  WHEN причина 2048 символов
  THEN передача успешна

AC-003-B4 Статус «Отменена» не мешает
  WHEN Анна передаёт TASK-51 Борису
  THEN передача успешна, статус «Отменена»

AC-003-B5 Скорость
  WHEN проект из 500 участников
  THEN p95 передачи ≤ 300 мс

## Frontend-половина
AC-003-F1 Кнопка
  WHEN карточку открыл её исполнитель
  THEN кнопка «Передать» видна
  WHEN карточку открыл не исполнитель (Вера)
  THEN кнопки нет

AC-003-F2 Причина
  WHEN получатель выбран, а причина пустая, из пробелов или длиннее 2048 символов
  THEN подтвердить нельзя, видно, что не так с причиной

AC-003-F3 Ожидание
  WHEN передача отправлена и ответа ещё нет
  THEN показано ожидание, результат не показывается

AC-003-F4 Успех
  WHEN API вернул успех
  THEN переход в «Мои задачи», сообщение «Задача <номер> передана: <имя получателя>»

## Границы
Вне slice: отказы с причинами, кроме NOT_ASSIGNEE и INVALID_REASON (004); доступ прежнего
исполнителя после передачи (005); обновление экранов других пользователей (007, 008); аудит (006).
Конфликт с 004: обе половины трогают диалог передачи — 003 делает успешный путь и валидацию
причины, 004 добавляет показ отказов сервера.
