# 007 — Передача видна без перезагрузки

Тип: поведение
Основание: FR-9 (новый исполнитель, руководитель), FR-12
Зависимости: 001, 003
Половины: backend — tasks-core (публикация) + socket-service (доставка); frontend. Три Change, три PR, принимаются вместе
Результат: новый исполнитель и руководитель видят передачу сразу, прежний исполнитель получает сообщение

## Контракты
- contracts/events/task-transferred.realtime.schema.json — не меняется
- contracts/socket/task-transferred.message.json — не меняется

## Общая приёмка (собранное приложение)
AC-007-1 Новый исполнитель
  WHEN у Бориса открыты «Мои задачи»
   AND Анна передала ему TASK-42
  THEN TASK-42 появилась в списке Бориса без перезагрузки

AC-007-2 Руководитель
  WHEN у Веры открыта TASK-42
   AND Анна передала её Борису
  THEN исполнитель в карточке у Веры — Борис, без перезагрузки

## Backend-половина
tasks-core:
AC-007-B1 Событие на передачу
  WHEN передача TASK-42 успешна
  THEN публикуется realtime-событие с прежним (Анна) и новым (Борис) исполнителем
  WHEN передача отклонена
  THEN событие не публикуется

socket-service:
AC-007-B2 Адресаты
  WHEN получено событие о передаче TASK-42 Анна → Борис
  THEN сообщение получают все подключения Анны, Бориса и Веры
   AND Глеб и Дина его не получают

AC-007-B3 Офлайн
  WHEN Борис не подключён в момент передачи
   AND подключился позже
  THEN пропущенное сообщение ему не досылается

## Frontend-половина
AC-007-F1 Новый исполнитель
  WHEN пришло сообщение, где пользователь — новый исполнитель
  THEN задача добавлена в «Мои задачи»

AC-007-F2 Руководитель
  WHEN пришло сообщение по открытой у руководителя задаче
  THEN в карточке и списке обновлён исполнитель

AC-007-F3 Вход после офлайна
  WHEN Борис открыл приложение после передачи
  THEN TASK-42 в «Моих задачах», отдельного уведомления о передаче нет

## Границы
Вне slice: реакция у прежнего исполнителя (закрытие карточки, тост, удаление из списка) — 008.
Порядок при быстрых передачах — 009. Конфликт с 006: общая точка публикации в tasks-core.
