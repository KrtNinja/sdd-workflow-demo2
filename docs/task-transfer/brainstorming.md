# Передача задачи — Brainstorming

Исходный запрос: **«Передача задачи на другого пользователя»**.
Затронутые сервисы: frontend, tasks-core, audit, socket-service (и user-core как источник данных об участниках).

Агент задаёт вопросы по одному и предлагает варианты. Решает человек.
Из этой таблицы собирается Dev Spec. Документ — протокол решений, его не правят задним числом:
решения, принятые позже (на ревью slices), записаны в отдельном разделе.

## Что агент решил бы сам, если отдать задачу одним промптом

| Вопрос | Вероятная догадка агента | Чем плохо |
|---|---|---|
| Кто может передать | Любой с правом правки или админ | Продукт хотел «только исполнитель»; админская передача — отдельная фича |
| Что с прежним исполнителем | Остаётся наблюдателем | По решению он теряет доступ к задаче целиком |
| tasks-core → audit | Синхронный вызов или fire-and-forget | Первое роняет передачу при сбое audit, второе теряет записи |
| Брокер недоступен | Ошибка пользователю | Передача должна пройти, события — дойти позже |
| Повтор запроса | Идемпотентный успех | Решено: отказ «Вы больше не исполнитель» |
| Сохранение после передачи | Общий «нет доступа» | Пользователь не понимает, что произошло |
| Быстрые передачи A → B → C | Порядок не важен | Устаревшее событие перетирает свежее у клиента и в журнале |
| Дубль события в audit | Две записи | Журнал аудита врёт о числе передач |

## Решения: продукт и фронтенд

| # | Вопрос | Решение |
|---|---|---|
| Q0 | Отличие от смены исполнителя | Раньше сменить исполнителя было нельзя вовсе |
| Q1 | Кто передаёт | Только текущий исполнитель |
| Q2 | Кому | Только активному участнику проекта |
| Q3 | Согласие получателя | Не нужно, передача сразу |
| Q4 | Прежний исполнитель | Задача пропадает из его списка, доступ теряется |
| Q5 | Кто видит задачу | Исполнитель и руководитель/админ |
| Q6 | Причина | Обязательна |
| Q7 | Статус | Сохраняется; закрытую передать нельзя |
| Q8 | Подзадачи | Их нет |
| Q9 | Массовая передача | Вне scope |
| Q10 | Где в UI | Кнопка в карточке |
| Q11 | Выбор получателя | Поиск по имени; в подсказке имя и должность |
| Q12 | Отклик UI | Ждать сервер; после успеха — «Мои задачи» и тост |
| Q13 | Email/push | Вне scope, только realtime |
| Q14 | Вторая вкладка прежнего исполнителя | Карточка закрывается с тостом, правки теряются |

|---|---|---|
| B1 | Задача закрыта, пока открыт диалог | Фронт закрывает её по сокету; если запрос дошёл — отказ с причиной |

| S1 | tasks-core → audit | Асинхронно через брокер |

## Решения после brainstorming

| Когда | Вопрос | Решение |
|---|---|---|
| Ревью риска | Задача уволенного исполнителя | Админская передача — отдельная фича |
| Ревью риска | Ложный отказ при повторе | Оставляем |
| Dev Spec | Финальные статусы | Только «Закрыта» |
| Dev Spec | Причина | До 2048 символов |
| Dev Spec | Поиск | С 2 символов, до 20; ФИО, подстрока, без регистра; начало слова выше, затем алфавит; пауза 200 мс |
| Dev Spec | Задержка аудита | p95 ≤ 1 с |
| Ревью slices | Кто ищет кандидатов | Любой, кто видит задачу |
| Ревью slices | Повторное нажатие в UI | Кнопка неактивна до ответа; в закрытой задаче кнопки нет |
| Ревью slices | Отказ при сохранении после передачи | TASK_TRANSFERRED, тост без имени получателя |
| Ревью slices | Дубль в аудите | Одна запись |
| Ревью slices | «Руководство» | Руководитель проекта + администраторы организации |
| Ревью slices | Контракты | У каждого сервиса свои, владелец — публикующий |
| ADR-0001 | Доставка | Outbox в PostgreSQL tasks-core, Kafka с ключом по задаче, `transferSeq` |

Самые дорогие решения — S1, S2 и S7. Их бы не поймали на ревью кода: ошибка проявилась бы
только при сбое брокера или гонке передач в проде.
