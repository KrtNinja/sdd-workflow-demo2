## Why
Slice 003 — передача задачи, backend-половина. Вход: `docs/task-transfer/slices/003-transfer.md`
(AC-003-B1 … AC-003-B5, серверная часть AC-003-1).

## What Changes
- use case `TransferTask`: исполнитель задачи → получатель, причина; статус не меняется
- проверка «вызывающий — текущий исполнитель» → `NOT_ASSIGNEE`
- проверка причины: не пустая, не из одних пробелов, не длиннее 2048 → `INVALID_REASON`
  (обработка пробелов по краям — после ответа на JIT-вопрос)
- условное обновление исполнителя: передача проходит, только если исполнитель не сменился
  с момента чтения
- поле `transferSeq` у задачи, +1 в транзакции передачи (ADR-0001)
- контроллер `POST /tasks/{id}/transfer` по контракту 001 вместо заглушки 501

## Impact
- `domain/task` — новое поле `transferSeq`, миграция со значением 0 для существующих задач
- `TaskRepository` — новый метод условного обновления; `save()` не меняется
- Публикация событий не затрагивается (006, 007)
- Проверки получателя не затрагиваются (004)
- Frontend — отдельный Change в своём репозитории
