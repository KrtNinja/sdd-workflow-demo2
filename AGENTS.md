# AGENTS.md

Правила процесса для фичей, которые затрагивают несколько сервисов. Агент читает этот файл
в каждой сессии. Здесь нет ничего про конкретную фичу. Правила кода каждого сервиса —
в AGENTS.md его репозитория.

## Сервисы
| Сервис | Роль |
|---|---|
| frontend | UI |
| tasks-core | задачи, правила передачи; PostgreSQL; публикует события в Kafka |
| audit | журнал аудита; читает события из Kafka |
| socket-service | realtime-доставка клиентам; читает события из Kafka |
| user-core | участники проектов, роли, активность (только чтение) |

## Где что лежит
| Что | Где | Живёт |
|---|---|---|
| Протокол решений | `docs/<feature>/brainstorming.md` | постоянно |
| Бизнес-поведение | `docs/<feature>/spec.md` | постоянно |
| Работы и приёмка | `docs/<feature>/slices/` | постоянно |
| Технические решения | `docs/adr/` | постоянно |
| Контракты | в репозитории сервиса-владельца | постоянно, источник правды |
| План реализации slice | `openspec/changes/<id>/` в репозитории сервиса | удаляется перед мержем |

## Slices на несколько сервисов
- Половина slice — это сервис. На каждый сервис свой Change и свой PR; slice принят, когда влиты все.
- AC-ID: `AC-NNN-k` — общая приёмка; `AC-NNN-Bk` — сервер (в slice подписано, какой сервис); `AC-NNN-Fk` — фронтенд.
- Каждый AC — в отдельном блоке кода, WHEN/THEN/AND на своих строках.
- Контракт события принадлежит сервису, который его публикует. Потребители ссылаются на его версию.

## Тестирование
- Название теста начинается с AC-ID: `AC-006-B6 повторная доставка даёт одну запись`
- Общая приёмка slice — на собранном приложении со всеми сервисами

## Процесс
- Работаем только по одобренному slice. Нет slice — нет кода.
- Перед реализацией: `/opsx:propose <id> по <файл slice>`, затем `/opsx:apply`.
  Откуда агент берёт файл slice в репозитории сервиса — см. подсказку в `docs/<feature>/changes.md`.
- Change не вводит нового поведения: каждый сценарий ссылается на AC-ID или помечен как технический.
- Неясность в требованиях → вопрос человеку. Ответ сначала попадает в Dev Spec и slice.
- Потребители событий идемпотентны: доставка at-least-once (ADR-0001).
- Перед мержем: решения из Change → ADR или описание PR, ловушки кода → AGENTS.md сервиса,
  папка Change удаляется. `/opsx:archive` не запускаем.
