## Что агент нашёл в коде

> Кода сервисов в демо нет. Ниже — предполагаемое состояние frontend после 001 и 002,
> как если бы агент его прочитал.

- Поле выбора получателя с поиском уже есть из 002 (`features/task-transfer/RecipientPicker`).
  Диалог передачи собирается вокруг него, второй поиск не пишется.
- API-клиент сгенерирован из `tasks-core.openapi.yaml` (001): метод `transferTask` есть, вызывать
  его нужно через `shared/api`, а не напрямую.
- Признак «текущий пользователь — исполнитель» в карточке уже вычисляется для кнопки смены статуса.
  Кнопку «Передать» показываем по тому же признаку плюс «статус не "Закрыта"» (AC-003-F1).
- Тосты: общий `shared/toast` переживает переход между страницами, отдельный механизм не нужен.
- В карточке задачи черновик комментария и правки описания живут в локальном состоянии,
  автосохранения нет. После успешной передачи карточка закрывается (AC-003-F4) — несохранённое
  в **этой** вкладке пропадёт. Для других вкладок Dev Spec это решает (FR-9: правки теряются),
  для текущей — нет.
  → **продуктовый вопрос**, см. ниже.
